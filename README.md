# 发言频率控制（talk-rate）

一个 MaiBot 第三方插件：**把群聊回复频率精确控制到 0**，让「某个群只在被 @ 时才回复」真正成立。

原版 MaiBot 的频率下限是 `0.01`，而且即使你把全局配置改成 `0`，@ 也不会再触发回复——
这个插件解决的正是这个问题。

- 插件 ID：`github.winincorce-a11y.talk-rate`
- 组件：2 个 `@HookHandler`、1 个 `@Command`、1 个 `@Tool`
- 不修改 MaiBot 主程序代码

---

## 为什么原版做不到

这不是配置没调对，而是主程序的判定顺序决定的。

`src/maisaka/runtime.py::_get_effective_reply_frequency()` 返回 0 时：

1. `src/maisaka/turn_trigger/scheduler.py::_evaluate()` **第一个命中的分支**是「静默消费」，
   @ 强制触发的判断（`_has_forced_turn_trigger()`）排在它**后面**，根本没机会执行；
2. `src/maisaka/reasoning_engine.py::_handle_silent_turn()` 第一行就是
   `self._runtime._clear_forced_turn_state()`，把刚刚因 @ 而设置的强制触发**主动清掉**。

所以「频率 = 0」在原版里等于**彻底闭嘴**，连 @ 都没用。你能用的最低值就是 `0.01`，
而 `0.01` 仍会让普通聊天内容有一定概率触发回复。

## 本插件怎么做

不去硬改频率数值，而是把「说不说话」从消息接收链路上摘出来，只作用于**回复**本身：

| 阶段 | Hook | 行为 |
| --- | --- | --- |
| 入站 | `chat.receive.after_process` | **只记录判定结果，从不 abort**。消息照常进入命令链，其他插件（随机图片、点歌、查询等）完全不受影响 |
| 规划器 | `maisaka.planner.before_request` | 本轮不该回复时，把 `reply` 工具从 `tool_definitions` 里摘掉 |
| 出站 | `send_service.before_send` | **真正生效的拦截点**：本轮不该回复时取消这条消息。只拦「麦麦的闲聊回复」，命令输出与非文本消息放行 |

判定优先级：**临时设置 → 白名单 → 逐群规则 → 默认规则**。

### 为什么出站放行规则这么设计

`reply` 在 Maisaka 里是 **deferred（延迟）工具**，规划器顶层工具表里本来就没有它
（要靠 `tool_search` 才检索出来），所以在规划器摘 `reply` 实际拦不住回复——
真正的闸门必须在出站。

但出站闸门不能一刀切，否则 `/tr 0` 之后连别的插件都残废：

- **命令消息**（含 `随机图片` 这种**不带斜杠**的触发词）入站时会登记一次性豁免，其输出放行；
- **图片 / 表情 / 转发 / 语音**等非文本出站一律放行，它们几乎都来自别的插件；
- 只剩「普通聊天触发的纯文本回复」才会被拦。


> **为什么入站阶段不拦消息**：`chat.receive.after_process` 的 abort 发生在主程序命令链
> （`bot.py` 的 `_process_commands`）**之前**。一旦在入站阶段 abort，所有其他插件的命令
> ——包括像 `随机图片` 这种**不带斜杠**的触发词——都会一起失效。
> 本插件只负责「麦麦说不说话」，不该替别的插件决定它们收不收得到消息。

> **规划器阶段拿不到消息内容**：`maisaka.planner.before_request` 只有 `session_id`，
> 没有 `message` / `is_at`。所以「这一次到底有没有 @ 我」必须在入站阶段记下来，
> 由规划器按 `session_id` 取回（默认 180 秒内有效）。

## 安装

把整个 `mai-talk-rate/` 目录放进 MaiBot 的 `plugins/` 下：

```
MaiBot/
└── plugins/
    └── mai-talk-rate/
        ├── _manifest.json
        ├── plugin.py
        └── ...
```

重启（或在 WebUI 插件页重载）后，插件会自动出现在插件列表里。
首次启动会自动生成 `config.toml`。

## 配置

在 WebUI 的插件配置页里改，或直接编辑 `plugins/mai-talk-rate/config.toml`。

配置页里每个字段都有中文名称和说明；`rules`、`keywords` 是多行输入框，
`keyword_match` 是下拉选择，按界面提示填即可。

```toml
[plugin]
enabled = true

[default_rule]
group_rate = "default"        # default = 沿用原版；0 = 没被 @ 就不说；也可以 0.05 / 5%
private_rate = "default"      # 私聊，同样写法
blocked_whitelist = ""        # 永远不拦截的群号/会话，逗号分隔

[group_rules]
# 每行 `群号=频率`，# 或 // 开头是注释
rules = """
123456789=0                  # 这个群只有被 @ 才回复
987654321=0.05              # 这个群约 5% 概率回复
111111111=default           # 这个群沿用原版频率
"""
at_bypass = true              # 频率为 0 时，被 @ / 被叫名字是否仍然回复

# 关键词放行：命中这些词时，即使频率为 0 也会回复
keywords = """
麦麦
你好，在吗，帮我看看
"""
keyword_match = "contains"      # contains / prefix / exact / regex
keyword_case_sensitive = false  # 是否区分大小写
```

频率写法：`0`、`0.05`、`5%`、`on`（=1）、`off`（=0）、`default`（沿用原版）。

> `*=0` 这种通配规则**只作用于群聊**，不会误伤私聊。

### 关键词放行

被限频的会话（包括 `/tr 0` 的「只 @ 才回复」）里，只要消息命中关键词就会正常回复。
关键词优先级**高于 `@`**：即使关掉 `at_bypass`，关键词也照样生效。

| 匹配方式 | 含义 | 例子（关键词 `麦麦`） |
| --- | --- | --- |
| `contains` | 包含即可（默认） | `请问麦麦在吗` ✅ |
| `prefix` | 必须以关键词开头 | `麦麦你好` ✅ / `你好麦麦` ❌ |
| `exact` | 必须完全相等 | `麦麦` ✅ / `麦麦你好` ❌ |
| `regex` | 按正则解释 | `第\d+号` 匹配 `请看第3号` ✅ |

写法：一行一个或逗号分隔，`#` 与 `//` 开头是注释。
配好后发 `/tr` 能看到「关键词：N 个（方式）…」，用来确认是否读到。

## 命令

在群里直接发（需要操作员权限，见 `bot_config.toml` 的 `[plugin] permission`）：

| 命令 | 作用 |
| --- | --- |
| `/tr` | 查看当前会话规则，以及「为什么说 / 不说」 |
| `/tr 0` | 当前会话：只有被 @ 或命中关键词才回复 |
| `/tr 5%` | 当前会话：5% 概率回复，@ 与关键词必回 |
| `/tr set 123456789 0` | 指定群号，不用切群 |
| `/tr reset` | 清除当前会话的临时设置，恢复配置规则 |
| `/tr help` | 帮助 |

`/tr` 系列命令**永远穿透**所有限制——否则一旦把自己设成 0，就再也调不回来了。
命令执行结果会**直接发到 QQ**，在群里立刻能看到，不用去翻日志或 WebUI。

临时设置会写到插件的 `data_dir/state.json`，重启后仍然生效。

## 验收方法

配置 `123456789=0` 之后，在那个群里：

- 随便聊天 → 麦麦**不应**回复，日志里能看到 `发言频率控制：本轮摘掉 reply 工具`；
- `@麦麦 在吗` → 麦麦正常回复；
- `随机图片`、`/clear` 等其他插件的命令 → **照常工作**（这是入站不再 abort 的直接结果）。

## 已知边界

- **消息仍会进上下文**：为了不误伤其他插件，本插件不再拦截入站消息。
  普通聊天会正常进入麦麦的上下文与历史，只是规划器拿不到 `reply` 工具。
  代价是这些消息仍会占用上下文与 token——这是「不影响其他插件」换来的取舍。
- **主动消息不受限**：由 `maisaka.proactive.trigger` 等触发的主动发言不经过 `chat.receive`，
  频率 0 时仍可能出现。需要连它一起关，请用主程序的主动聊天开关。
- **没有入站记忆时不主动开口**：插件热重载后的第一批消息可能没有入站记忆，
  此时零频率会话按「不主动回复」处理，宁可不说话也不误发。
- **判定发生在解析阶段**：`is_at` / `is_mentioned` 以主程序解析结果为准；两者都为真时按 @ 处理。
- 本插件只管「说不说」，不改写作风格、不管回复长度。
